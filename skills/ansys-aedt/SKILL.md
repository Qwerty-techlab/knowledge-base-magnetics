# Ansys AEDT через PyAEDT

Сервер `ansys_aedt` (PyAEDT-MCP 4.0.0b1) даёт живую Python-сессию с AEDT. Установлено: **AEDT 2024 R2**, `C:\Program Files\AnsysEM\v242\Win64`. Лицензия: `1055@localhost`.

## Переносимость и границы проверки

Это копия рабочего скилла, а не подтверждение наличия MCP-инструментов на машине читателя. Перед использованием проверьте установленную версию AEDT/PyAEDT, лицензию и фактически доступную схему MCP. Приведённые ниже пути, порт лицензии и конфигурация описывают исходное рабочее окружение и не должны применяться вслепую. `<USER_HOME>` в приложениях заменяется локальным домашним каталогом.

Для доказательств сходимости и сохранения проекта используйте соседний `../electromagnetic-fem-verification/SKILL.md`. Описания чужих скиллов (`documents`) не означают, что они входят в этот репозиторий. При отсутствии такого скилла используйте доступные средства отчётности без выдумывания инструментов.

Скрипт `scripts/fem_journal.py` ведёт SQLite-журнал без запуска AEDT. Всегда задавайте `--db` вне репозитория, например `python scripts/fem_journal.py --db /path/to/project/journal.sqlite3 init`. Проверены создание БД и чтение summary. Живое подключение к AEDT при публикации этой копии не тестировалось.

## Границы применимости — прочитать до начала

**Физику этот инструмент не проверяет.** Скрипт может быть корректен как код и бессмыслен как постановка задачи: неверные граничные условия, слишком грубая сетка, ложная сходимость, неподходящий тип решателя. Ответственность за постановку и осмысленность результата — на пользователе. Не подавайте результат расчёта как проверенный вывод — сообщайте, что именно было посчитано и при каких допущениях.

**Лицензия конечна.** `launch_aedt` занимает лицензию AEDT и держит её всю сессию. Перед запуском проверьте `check_aedt_status` — возможно, AEDT уже открыт и нужен `connect_to_aedt`, а не второй экземпляр. Не оставляйте висящие сессии: `disconnect_from_aedt` по завершении.

**Расчёт долгий.** `analyze_design` на реальной модели идёт минуты или часы. Не запускайте его без явной просьбы. Перед запуском скажите, сколько примерно ждать, и уточните, точно ли считать сейчас.

**`run_python_code` исполняет произвольный код** в сессии AEDT с правами пользователя — может изменить или удалить проект. Перед записью в существующий проект пользователя спросите. Читающие операции (`list_designs`, `get_model_info`, `screenshot`) — свободно.

## Порядок работы

1. `check_aedt_status` — есть ли уже сессия. **Всегда первым.**
2. `connect_to_aedt` если AEDT запущен, иначе `launch_aedt`.
3. `list_projects` / `list_designs` / `get_model_info` — осмотреться, если проект чужой.
4. Работа: готовые инструменты где есть, `run_python_code` где нет.
5. `screenshot` — проверить геометрию глазами. Для EM-модели это не формальность: геометрия легко собирается корректно по коду и неверно по факту.
6. `save_project` явно. Автосохранения нет.
7. `disconnect_from_aedt`.

При ошибке — `get_pyaedt_logs`, там причина подробнее, чем в тексте исключения.

## Инструменты

Всегда доступны: `check_aedt_installed`, `check_aedt_status`, `launch_aedt`, `connect_to_aedt`, `get_pyaedt_logs`.

После подключения: `disconnect_from_aedt`, `clear_aedt`, `list_projects`, `list_designs`, `open_project`, `save_project`, `create_design`, `analyze_design`, `export_config`, `export_results`, `run_python_code`, `run_python_script`, `get_model_info`, `screenshot`.

С флагом `--include-context` (включён): `get_guidelines_for` — методические указания по workflow AEDT. Вызывайте его при незнакомом типе задачи, прежде чем писать код.

`create_design` штатно покрывает **HFSS, Maxwell, Icepak, Circuit**.

## SIwave — важное ограничение

**Готовых инструментов для SIwave нет ни в одном MCP-сервере.** Работа только через `run_python_code` с прямыми вызовами PyAEDT. То есть MCP здесь — транспорт, а не обёртка: выигрыш сводится к тому, что видны трейсбеки и живёт состояние сессии.

Для layout-задач (PCB, целостность сигналов, питание) обычно нужен не класс `Siwave`, а **EDB** — работа с базой layout напрямую, без запуска GUI. Шаблоны — в `references/pyaedt-snippets.md`.

SIwave установлен: `siwave.exe`, `siwave_ng.exe` в `C:\Program Files\AnsysEM\v242\Win64`. Переменная `SIWAVE_INSTALL_DIR` задана.

## PyAEDT-код

Шаблоны под Maxwell 2D/3D, HFSS, Q3D, Icepak, EDB/SIwave, параметрику и Optimetrics, экспорт результатов — в `references/pyaedt-snippets.md`. Читайте перед написанием кода: там же типовые ошибки на версии 2024 R2.

Ключевое про `run_python_code`: сессия **persistent**, переменные живут между вызовами. Открыли проект — дальше работаете в нём, переоткрывать не нужно. Это же значит, что мусор в namespace накапливается — при странном поведении проверьте, не осталось ли старой переменной.

Всегда указывайте версию явно при создании объектов вне готовых инструментов:

```python
from ansys.aedt.core import Maxwell3d
m3d = Maxwell3d(version="2024.2")
```

Без `version` PyAEDT может выбрать другую установку или упасть.

## Известная проблема на 2024 R2

В community-сервере `LaplaceYoung/ansys-aedt-mcp` конструкторы решателей (`Hfss(...)` и аналоги) **отваливались по таймауту именно на AEDT 2024 R2** при смоук-тестах. Официальный `pyaedt-mcp` установлен как основной именно поэтому. Если конструктор всё же зависает — попробуйте `non_graphical=True` и увеличьте таймаут, либо подключайтесь к уже открытому вручную AEDT через `connect_to_aedt`.

## Отчёты по результатам

Для оформления результатов расчёта в Word/Excel/PDF используйте скилл `documents`. Типовой маршрут: `export_results` из AEDT → таблица через `create_excel_from_markdown` или отчёт через `create_word_from_markdown`, графики и скриншоты вставляйте как изображения.

## Установка

Сервер запускается через `uvx` из git, без локального venv:

```
uvx --from git+https://github.com/ansys/pyaedt-mcp.git ansys-aedt-mcp --version 242 --graphical --include-context
```

Прописан в `%APPDATA%\Claude\claude_desktop_config.json` как `ansys_aedt`. Флаг `--graphical` — чтобы видеть, что происходит в GUI; для batch-расчётов уберите его или добавьте `--non-graphical`.
