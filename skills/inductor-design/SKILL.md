# Расчёт силового дросселя

## Обязательная область применимости

Используй комплект только для идеализированного boost-преобразователя в режиме непрерывного тока (CCM):

- один дроссель с одним физическим зазором;
- interleaved boost с независимым дросселем каждой фазы и одним физическим зазором в каждом магнитопроводе.

Не выдавай результат этого движка за расчёт buck, buck-boost, граничного или прерывистого режима, связанного interleaved-дросселя либо нескольких обмоток на общем магнитопроводе. Для такой задачи сначала требуется отдельная расчётная модель.

## Перед расчётом

1. Прочитай [calculation-contract.md](references/calculation-contract.md), [report-contract.md](references/report-contract.md), [result-contract.md](references/result-contract.md) и, перед 3D-моделированием, [fem-winding-geometry-contract.md](references/fem-winding-geometry-contract.md).
2. При изменении формул найди соответствующий раздел в [канонической методике](references/Metodika_VCh_silovykh_drosseley_bez_rascheta.tex). Используй её как исходную проверяемую модель, а не как истину a priori.
3. Присвой каждому существенному числу статус: исходное требование, паспортное значение, аналитическая оценка, сошедшийся FEM-результат либо измерение. Не смешивай статусы в одном выводе.
4. Проверь ТЗ на противоречия. Если `P_вых ≠ U_вых · I_вых`, явно зафиксируй принятое правило в конфигурации и отчёте.
5. Не используй значения из предыдущего проекта как входные данные нового расчёта.

## База знаний и иерархия доказательств

Корень всей базы находится на два уровня выше реального каталога скилла. При глобальной установке через ссылку сначала разреши реальный путь скилла, затем используй соседние `articles/`, `components_db/` и канонический файл `articles/06_textbooks_ru/_methodology_source/Metodika_VCh_silovykh_drosseley_bez_rascheta.tex`.

Не загружай все статьи заранее. Для конкретной формулы или свойства найди релевантный источник через поиск по базе, проверь область применимости и сохрани ссылку на страницу, рисунок, таблицу или кривую. Источник, паспорт, CAD, аналитический код и прежний отчёт не считаются истинными автоматически.

При конфликте руководствуйся [контрактом расчёта](references/calculation-contract.md). Сошедшийся FEM-результат относится только к точной геометрии, материалу, возбуждению, температуре, сетке и граничным условиям конкретного прогона.

## Коррекция методики по FEM

Перед признанием расхождения физическим исключи ошибки единиц, геометрии, витковости, возбуждения, нормировки 2D/3D, свойств материала, внешней области и постпроцессинга. Для принимаемой величины сохрани не менее трёх сопоставимых сеток, исследование размера области и независимую энергетическую либо потоковую проверку.

Если проверенный FEM-анализ опровергает формулу, коэффициент или подстановку:

1. сохрани проект решателя, входные параметры, таблицу сходимости, машинные результаты и скриншоты полей;
2. зафиксируй старое и новое выражение, численное влияние и границы применимости;
3. исправь канонический LaTeX и синхронизируемые копии;
4. возле каждой такой правки явно напиши в видимом тексте и LaTeX-комментарии: `Исправлено на основании FEM-анализа`, указав идентификаторы прогонов и артефактов;
5. не обобщай результат за пределы проверенной постановки без дополнительного расчёта или измерения.

## Геометрия 3D FEM

Переноси укладку из актуального расчётного JSON в MCAD/Maxwell строго по
`winding_layout` и алгоритму `make_drawings.py`. Не заменяй дискретные
параллельные кабели монолитным блоком или произвольной спиралью. Сердечник и
обмотка находятся в общей системе координат; до сетки обязательны численный
геометрический gate, проверка сохранности CAD и скриншот модели из графической
сессии AEDT для ревью. Полные правила приведены в
[контракте геометрии обмотки](references/fem-winding-geometry-contract.md).

## Автоматический запуск по минимальному ТЗ

Требуются Python 3.10+ и зависимости из `requirements.txt`.

Скопируй `assets/tz_input.example.json`, измени только исходные данные нового ТЗ и выполни:

```powershell
python scripts/calculate.py --tz <tz_input.json> --output <новый_проект>
```

Команда до создания проекта проверяет JSON по `references/tz-input.schema.json`, согласует мощность и ток, создаёт автономный проект, формирует полный `design_config.json`, выполняет полный перебор, строит рисунки и отчёты, затем запускает тесты и валидатор.

## Ручное создание и пересчёт проекта

Создай автономную копию шаблона:

```powershell
python scripts/create_project.py <путь_проекта> --name <имя>
```

Для ручного режима заполни `<проект>/2_input_files/design_config.json`. Для преобразования минимального ТЗ в конфигурацию существующего проекта выполни:

```powershell
python scripts/prepare_config.py <tz_input.json> <путь_проекта>
```

Включи только нужные варианты `single.enabled` и `interleaved.enabled`. Не меняй расчётные константы и диапазоны перебора в Python вместо секций `tz` и `search`.

Если база не находится автоматически, задай `knowledge_base_path` абсолютным путём либо переменную `INDUCTOR_KNOWLEDGE_BASE`.

## Выбор компонентов

Выполняй полный численный перебор всех полностью описанных сочетаний:

`сердечник × материал × литцендрат × число параллельных проводов × N`.

Предпочтительные семейства по исходному техническому заданию: `EQ`, `ETD`, `PM`, `PQ`, `RM`, `EER`. Семейство `E` резервное. Выбирай `E` только при `preferred_feasible = 0` после полного перебора и приводи численные причины отклонения предпочтительных вариантов.

Записи `screened_out` являются только предварительным отсевом. Если такой предпочтительный типоразмер проходит предварительную проверку, сначала догрузи официальный даташит, полную геометрию, параметры окна, `A_L0`, совместимые материалы и данные зазора в `components_db/cores.json`; затем повтори полный перебор. Нельзя объявлять отсутствие предпочтительного решения по неполной базе.

Исторические поля `status`, `notes` и `_meta.origin` в базе не являются критерием выбора.

## Запуск

Из каталога скилла выполни:

```powershell
python scripts/run_pipeline.py <путь_проекта>
```

Последовательность обязательна: расчёт → рисунки → отчёт → валидация. Отсутствующий обязательный рисунок должен завершать сборку ошибкой.

Для отдельной проверки:

```powershell
python scripts/validate_project.py <путь_проекта>
```

## Неподтверждённые результаты

До получения реальных данных всегда оставляй итоговый статус `analytical_preliminary`. Не утверждай, что выполнены метод конечных элементов (МКЭ), тепловые испытания, измерение `L_diff(I)`, первого резонанса или электромагнитной совместимости, если соответствующих артефактов нет.

Не повышай статус FEM-результата только из-за успешного завершения решателя. Требуются проверенная геометрия, воспроизводимые настройки, сходимость принимаемых величин и сохранённые артефакты. Максимум поля в идеально острой кромке не используй как сошедшуюся величину; сначала задай физический радиус или диапазон радиусов.

Зазор задавай через целевой `A_L`; геометрический размер `g` является расчётной оценкой до МКЭ и измерительной доводки.

## Количество магнитопроводов

- Один отдельный дроссель: один комплект, две половинки.
- `n` независимых фазных дросселей: `n` комплектов, `2 · n` половинок.
- Частотные варианты альтернативны и не суммируются в одной спецификации.

## Перед передачей результата

Убедись, что:

- в отчёте есть все 13 разделов и ненумерованный список источников;
- таблица сравнения содержит все пары сердечник–материал и численные причины отказа;
- выбранные марки, частоты, мощность, число фаз и количества совпадают с JSON;
- в выводах нет марок или чисел из предыдущего проекта;
- `k_R` означает только `ℛ_g/ℛ_c`, а запас резонанса обозначен `k_f`;
- итоговый `.docx` проходит проверку OOXML.
