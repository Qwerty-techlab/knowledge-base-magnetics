# Контракт геометрии обмотки для 3D FEM

## 1. Назначение

Документ задаёт правила переноса дискретной укладки из расчётного JSON и
`make_drawings.py` в MCAD и Maxwell 3D. Он не содержит FEM-результатов и не
заменяет проверку конкретной модели.

## 2. Источник геометрии

Для выбранного варианта единственным источником раскладки являются поля
`selected.design.winding_layout` и `selected.wire` в актуальном расчётном JSON.
Старый CAD, скриншот или прежний FEM-проект не являются источником размеров.

Поля интерпретируются буквально:

- `parallel_axial` — число отдельных параллельных кабелей одного витка вдоль
  оси окна;
- `parallel_radial` — число отдельных кабелей одного витка по радиусу;
- `turns_per_bank_per_layer` — число витков одного осевого банка в одном
  радиальном слое;
- `turns_per_layer` — сумма витков верхнего и нижнего банков в слое;
- `n_layers` — число радиальных слоёв;
- `group_axial_mm` и `group_radial_mm` — габариты группы параллельных кабелей
  одного витка;
- `turn_pitch_mm` — шаг между витками внутри осевого банка, а не шаг радиальных
  слоёв;
- радиальный шаг слоёв равен
  `group_radial_mm + interlayer_insulation_mm`;
- ближайшая к зазору координата определяется `gap_keepout_half_mm`.

Алгоритм координат должен совпадать с `3_calc/make_drawings.py`. До построения
3D-модели требуется заново сформировать рисунок укладки из того же JSON.

## 3. Дискретные проводники

Расчётная дискретная укладка означает физические кабели, а не эквивалентный
монолитный блок:

- каждый виток содержит `wire.n_parallel` отдельных кабелей;
- наружный диаметр каждого кабеля равен `wire.d_outer_mm`;
- запрещено заменять группу диаметром `d` виртуальным диаметром
  `d·sqrt(n_parallel)` в опорной модели потерь;
- соседние тела не должны пересекаться или касаться вследствие округления
  координат;
- витки должны образовывать наматываемые непрерывные пути с допустимым радиусом
  изгиба, а не набор несвязанных колец или диагональную спираль, не
  соответствующую рисунку укладки.

Гомогенизированный проводник допускается только как отдельная быстрая магнитная
модель для L и общего поля. Его сечение, ток, MMF и ограничения должны быть
явно записаны; результаты потерь и локального поля около зазора по нему не
принимаются без сравнения с дискретной моделью.

## 4. Секционная обмотка

Если обмотка разделена на два осевых банка:

- каждый банк строится как самостоятельная наматываемая секция;
- для двух секций предпочтительны четыре `CoilTerminal`: P/N каждой секции;
- последовательное соединение задаётся электрически в Maxwell/Circuit;
- физическую перемычку около зазора не добавляют, если она не предусмотрена
  конструкцией: на неё действует поле выпучивания и её потери требуют отдельной
  проверки;
- если перемычка неизбежна, её проводят вне зоны повышенного поля и принимают
  только после сравнения карт B/J и потерь с вариантом без перемычки.

В Maxwell 3D один `CoilTerminal` назначают ровно на одну торцевую грань. Нельзя
скрывать несколько граней в одном внешнем терминале.

## 5. Сердечник и система координат

Сердечник и обмотку всегда строят в одной общей системе координат относительно
центра магнитопровода. Расчётная модель голой катушки не заменяет модель
дросселя.

- Используется официальный CAD выбранного сердечника, если он доступен.
- Половины ориентируют рабочими поверхностями друг к другу.
- Единственный физический зазор создают только на заданной поверхности
  центрального стержня; боковые стержни не раздвигают.
- Все тела центрируют и проверяют относительно одной плоскости зазора.

Для обмена с AEDT предпочтителен STEP/OCCT. STL допустим только после контроля
числа треугольников и памяти; высокополигональная STL-сетка не должна запускаться
без отдельного ресурсного gate.

## 6. Обязательный геометрический gate до сетки

До создания mesh и запуска solver сохранить машинный отчёт со следующими
проверками:

1. число сердечников, половин, секций, витков и кабелей;
2. bounding box, объём, число граней и рёбер каждого тела;
3. центральный и боковые зазоры;
4. минимальное расстояние меди до сердечника и кромки зазора;
5. объём пересечений медь–сердечник и проводник–проводник — строго ноль с
   документированным численным допуском;
6. непрерывность каждого токового пути и наличие ровно двух торцевых граней на
   секцию;
7. сохранение геометрии после import → save → read-only reopen;
8. SHA-256 исходного CAD и FEM-проекта.

Возвращаемое API значение `True` при импорте не считается доказательством
сохранности геометрии.

## 7. Визуальное ревью

После создания каждой итоговой модели в AEDT, но до mesh, требуется:

1. открыть проект в графической сессии;
2. выполнить `fit_all` и сохранить изометрический скриншот с различимыми
   сердечником, секциями и выводами;
3. передать скриншот на ревью;
4. не запускать mesh до подтверждения геометрии.

После успешного solve сохранить отдельные скриншоты B/H/J/энергии с легендами,
единицами и подписями. Потери и температуру показывают только из валидного
соответствующего расчёта.
