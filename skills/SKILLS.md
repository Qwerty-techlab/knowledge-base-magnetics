# Скиллы базы знаний

Рабочие процедуры для задач по расчёту силовых магнитных элементов.
Цель — не тратить токены на повторное извлечение того, что уже разобрано.

Корень базы: `C:\Users\user\Documents\Work\knowledge_base`

---

## Правила экономии токенов

Соблюдайте в первую очередь — это главная причина существования базы.

1. **Не читайте PDF.** Рядом с каждым `source.pdf` лежит `parsed.md` с извлечённым текстом.
   Читайте его. PDF открывайте только когда в `parsed.md` искажена таблица
   (в `metadata.json` поле `extraction_quality` подскажет, чего ожидать).
   **Формулы из `parsed.md` брать нельзя** — см. раздел «Формулы» ниже.
2. **Не собирайте параметры компонентов из даташитов заново.** Всё в `components_db/*.json`.
3. **Не читайте `BIBLIOGRAPHY.md` целиком, если нужна одна статья.** Ищите по ключевым словам
   grep-ом по `bibliography.json`.
4. **Не читайте статью целиком, если нужен один раздел.** В `parsed.md` есть маркеры
   `## [стр. N]` — ищите по ним.
5. Поле `use_in_methodology` в `metadata.json` говорит, зачем статья нужна, — часто этого
   достаточно, чтобы решить, читать её или нет.
6. **Формулу смотрите одной картинкой, а не страницей.** В `formulas/` лежат вырезки
   отдельных формул по 10–30 КБ. Открывать страницу целиком или PDF — впустую.

## Формулы — как читать достоверно

**Главное: формулам в `parsed.md` верить нельзя.** `parse_pdf.py` снимает только текстовый
слой, а формула в PDF — это отдельно позиционированные глифы; дробные черты и радикалы
вообще не текст, а векторная графика. Что происходит на практике:

| в PDF напечатано | в `parsed.md` попадает | почему |
|---|---|---|
| дробь $\frac{a}{b}$ | `a b` | черта — векторная линия, её нет в тексте |
| $\int_0^T$ | `Z T 0` или `R T 0` | глиф CMEX по позиции совпадает с `Z`/`R` |
| $\sum$ | `P` | то же, глиф CMEX |
| $\sqrt{x}$ | `x` | радикал — графика |
| $(\Delta B)^{\beta-\alpha}$ | `(∆B)β−α` | степень не отличима от умножения |
| $\mathrm{Re}\{\cdot\}$ | `Re` | фигурные скобки теряются |

Пример: iGSE из Muehlethaler в тексте выглядит как `Pv = 1 T Z T 0ki dB dt α (∆B)β−α dt`,
а в действительности это
$P_v = \frac{1}{T}\int_0^{T} k_i\left|\frac{dB}{dt}\right|^{\alpha}(\Delta B)^{\beta-\alpha}dt$.

**Порядок работы.** Формулы уже вырезаны в картинки — 1489 штук по всей базе, 300 dpi.

```
knowledge_base/articles/<тема>/<статья>/formulas/
    eq_p003_01.png     # стр. 3, первая формула
    index.json         # номер уравнения, страница, bbox, текстовый слой
    INDEX.md           # то же таблицей, для глаз
```

1. Нужна формула — найдите её в `formulas/index.json` по полю `eq_numbers`
   (номер уравнения из статьи) или grep-ом по `text_layer`.
2. Откройте соответствующий PNG. Это достоверный источник.
3. Перепишите формулу в LaTeX **в расчётный скрипт с комментарием-ссылкой**
   вида `# Muehlethaler 2011, ур. (2), formulas/eq_p002_01.png`. Тогда следующий раз
   картинку открывать не придётся.

**Ограничение, которое надо знать.** Определение областей построено на геометрии:
номер уравнения `(N)` у правого края колонки задаёт полосу, полоса вырезается на всю
ширину колонки. По шрифтам определять нельзя — у LaTeX-статей математика набрана
CMMI/CMSY (доля матшрифтов 5–10 %), а у IEEE обычным Times-Italic (0 %), и там формула
по шрифту неотличима от курсива в тексте. Отсюда следствия:

* ненумерованные формулы ловятся хуже нумерованных;
* попадается шум — строка прозы, стоящая вплотную к формуле, войдёт в полосу;
* у сканов без OCR не ловится ничего (`Legostaev_MEEU_uchebno_metodicheskoe_posobie` — 1 формула).

Перезапуск после добавления статьи:

```
python knowledge_base/skills/extract_formulas.py <папка_статьи>
python knowledge_base/skills/extract_formulas.py --all --dpi 400 --force   # вся база заново
```

## add-article — добавить статью в базу

1. Определить тему из таблицы выше. Новую тему заводить только если ни одна не подходит.
2. Придумать slug: `Автор_Год_Краткая_Тема` или `Издатель_Номер_Тема`, латиница, без пробелов.
3. Создать папку `articles/<topic>/<slug>/`, положить PDF как `source.pdf`.
4. Распарсить:
   ```
   python knowledge_base/skills/parse_pdf.py knowledge_base/articles/<topic>/<slug>
   ```
   Для двухколоночных статей с перемешанным текстом добавить `--layout`.
5. Вырезать формулы:
   ```
   python knowledge_base/skills/extract_formulas.py knowledge_base/articles/<topic>/<slug>
   ```
   Скрипт сам вписывает предупреждение в `parsed.md` и счётчик в `metadata.json`.
6. Добавить запись в `bibliography.json` → `entries`. Обязательные поля: `topic`, `title`,
   `title_source`, `application`, `keywords_ru`. Проставить `doi`, если он известен.
7. Перегенерировать библиографию:
   ```
   python knowledge_base/skills/make_bibliography.py
   ```
   Скрипт синхронизирует `metadata.json` и сверит библиографию с файловой системой.

**`title_source` заполнять честно:** `sources_md` / `pdf_metadata` — выверено;
`derived_from_filename` — заголовок угадан по имени файла. Не выдавайте угаданное за
выверенное и не придумывайте DOI.

## update-db — внести компонент в базу

Файлы: `components_db/cores.json`, `ferrite_materials.json`, `litz_wire.json`.

Общие правила:

- Сохранять структуру полей существующих записей. Отсутствующий в даташите параметр —
  `null`, а не выдуманное число.
- Расчётные (непаспортные) значения помечать суффиксом `_estimated` либо соседним полем
  `*_note` с пояснением.
- В `_meta.datasheet_sources` добавлять ссылку на даташит, откуда взяты данные.
- Проверять валидность после правки:
  ```
  python -c "import json;[json.load(open(f,encoding='utf-8')) for f in ['cores.json','ferrite_materials.json','litz_wire.json']];print('OK')"
  ```

**Сердечник** — обязательный минимум: `magnetic.A_e_mm2`, `A_min_mm2`, `l_e_mm`, `V_e_mm3`,
`winding.A_N_mm2`, `l_N_mm`, `mass_kg`, `A_L_ungapped_nH`. Без `A_N` и `l_N` нельзя считать
обмотку, без `A_min` — насыщение.

**Материал** — обязательный минимум: `mu_i`, `B_S_25C_T`, `B_S_100C_T`, `T_curie_C`,
`density_kg_m3` и полный блок `steinmetz` (`k_st`, `alpha`, `beta`, `fit_temperature_C`,
`fit_points`). Коэффициенты Штейнмеца **всегда** сопровождать точками подгонки — без них
неизвестна область применимости.

**Провод** — обязательный минимум: `n_strands`, `d_strand_mm`, `d_outer_mm`, `S_cu_mm2`,
`insulation.t_index_C`, `url`. `S_cu_mm2 = n_strands · π/4 · d_strand_mm²`,
`R_dc_mOhm_per_m = 17,2 / S_cu_mm2`.

## inductor-design — расчёт дросселя с нуля

Порядок работы, отработанный на проекте `drossel1`:

1. **Взять шаблон ТЗ** `prompts/inductor_design_template.md`, заполнить, положить
   в `2_input_files/prompt.txt` рабочей директории.
2. **Прочитать базы** `components_db/*.json` — библиотеки готовы.
3. **Написать расчётный скрипт** (Python). Требование: ТЗ меняется, поэтому расчёт живёт
   в скрипте, результат — в JSON, отчёт генерируется из JSON. Три файла:
   - `<name>_design.py` — расчёт → `results.json`
   - `make_drawings.py` — графики → `img/*.png`
   - `make_report.py` — Word из `results.json`
4. **Порядок расчёта:**
   - режим преобразователя: D, ΔI_L, I_rms, I_max, требуемая L
   - предварительная отбраковка по произведению площадей A_e·A_N
   - полный перебор: сердечник × материал × провод × число витков
   - для каждого варианта: зазор с учётом выпучивания (Liao & Chen), B_max в худшем
     случае, потери (iGSE + F_R по Sullivan), перегрев, собственная ёмкость и f_res
   - отсев по запасам, ранжирование выживших
5. **Обязательные проверки** (нормативные коэффициенты — в `ferrite_materials.json`,
   блок `normative_coefficients`):
   - B_max в худшем случае ≤ k_B·B_S(100 °C) − u_B
   - k_зан ≤ 0,70
   - k_R = f_res/f_sw ≥ 4
   - перегрев в пределах температурного индекса изоляции
   - ЭМС с запасом M_ЭМС относительно нормы
6. **В отчёте показать отклонённые варианты с числами** — не только выбранный.

Готовый образец на 1560 строк: `drossel1/5_interleaved/make_report_3ph.py`
(Word по ГОСТ Р 2.105, 13 разделов, 28 таблиц). Стилевые функции берутся импортом
из `drossel1/3_calc/make_report.py`, а не копированием.

## parse-pdf — извлечь текст из PDF

```
python skills/parse_pdf.py <файл.pdf|папка>       рядом появятся parsed.md и metadata.json
python skills/parse_pdf.py <папка> --layout       сохранять раскладку колонок
python skills/parse_pdf.py <папка> --force        перезаписать существующие
python skills/parse_pdf.py <папка> --max-pages 40 ограничить объём
```

Движок PyMuPDF, резервный — pypdf. Повторный запуск по папке безопасен: готовые `parsed.md`
пропускаются без `--force`.

Если `extraction_quality` в `metadata.json` — `«плохо: вероятно скан без OCR»`, текста в PDF
нет, нужен OCR (в базе такого нет; один русский учебник частично скан).

## Ловушки, проверенные на практике

- **Кодировка PowerShell.** Windows PowerShell 5.1 читает `.ps1` без BOM в ANSI — кириллица
  в скрипте ломает парсер с невнятной ошибкой «string is missing the terminator».
  Пишите вспомогательные скрипты на Python либо сохраняйте `.ps1` с BOM.
  Для вывода кириллицы из Python: `$env:PYTHONIOENCODING = "utf-8"`.
- **Дубликаты PDF.** В `0_references` нашлись две пары побайтовых дубликатов под разными
  именами. Перед добавлением партии проверяйте по MD5, а не по имени файла.
- **Ключи JSON.** Обращаясь к `results.json` из генератора отчёта, не угадывайте имена полей
  (`B_S_100_T` против `B_S_100C_mT`) — сначала выведите фактические ключи.
- **Никакого жёсткого индексирования** таблиц вида `table[4]` — ищите строку по ключу,
  иначе расчёт с другим набором вариантов молча подставит не те числа.
- **Формулы нельзя искать по шрифтам.** Логично предположить, что математика набрана
  матшрифтом (CMMI, CMSY, CMEX, Cambria Math), — но это верно только для LaTeX-статей
  (доля 5–10 %). У IEEE она набрана Times-Italic, доля матшрифтов ровно 0 %
  (проверено на Meng & Biela 2025, Papamanolis 2020, Jia 2024, Heldwein & Kolar 2008).
  Опирайтесь на геометрию: номер уравнения у правого края колонки.
- **Формула в PDF разбита на много мелких блоков.** У IEEE числитель, знаменатель и левая
  часть — отдельные блоки `rawdict`, каждый шириной 20–40 pt. Оценивать «похоже на формулу»
  по геометрии *внутри блока* бессмысленно: блок совпадает со строкой, и относительные
  отступы всегда нулевые. Считайте относительно колонки и собирайте полосу по вертикали.
- **`rawdict` не даёт `span["text"]`** — только `span["chars"]` с посимвольными bbox.
  В `dict` наоборот. Обращение к `span["text"]` на `rawdict` падает с `KeyError`.
- **Подписи на схемах похожи на формулы.** Метки вроде `CO`, `RL`, `DbL` внутри рисунка
  набраны курсивом с индексами и проходят любой разумный порог. Отбрасывайте блоки,
  целиком лежащие внутри bbox изображения.
